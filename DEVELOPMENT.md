# Working on Raynna's Tracker and Bestiary

Both interfaces ship in `RaynnaTracker`, saving `RaynnaTrackerDB`. The bundled
`ForeverHunt` dependency contains only a TOC to load old per-character saves.
Core copies legacy data on first initialization only when the new database is
absent. Never rewrite player save files during deployment. Existing frame names,
slash-handler keys and settings registry IDs remain stable compatibility contracts.

## Source map

| File | Responsibility |
| --- | --- |
| `Core.lua` | Saved data, creature observations, kill and loot attribution, money/XP totals, event routing |
| `UI.lua` | Tracker layout, rows, movement, resizing, scale input, reset confirmation, minimap launcher and `/rt` commands |
| `Bestiary.lua` | NPC/item source window, Alt-hover selection, pinning, source rows, portraits and tooltip layering |
| `Drops.lua` | Interactive collected-loot popup opened from a tracker row |
| `LootSources.lua` | Reference loot probabilities, reverse item lookup and bundled metadata |
| `Portraits.lua` | Session texture pool, loading queue and attachment to visible row/header hosts |
| `Widgets.lua` | Resize-cursor presentation, scrollbar behavior and number formatting |
| `Theme.lua` | Shared colors, backgrounds, borders and title-bar textures |
| `Demo.lua` | Separate, saved preview dataset for the tracker |
| `LootReference.lua` | Generated Classic creature/item/loot tables; do not hand-format |
| `Metadata.lua` | Generated standalone NPC/item/quest snapshot and faction overlays |
| `MetadataQueries.lua` | Version-aware optional provider with bundled/faction fallback |
| `PortraitDisplays.lua` | Generated creature-to-display-ID map; do not hand-format |

`RaynnaTracker.toc` defines loading order. Lua files receive the same namespace table
through `local _, Addon = ...`. File-local variables own transient state; methods
on `Addon` are the interface between modules. Window fields such as `money`, `xp`,
`scrollbar` and `portrait` are intentionally kept stable.

## Tracking data flow

1. `Core.lua` observes creature GUIDs and their names/levels.
2. `PARTY_KILL` records a kill once. Loot windows capture corpse provenance;
   confirmed loot messages consume that provenance rather than guessing a source.
3. Character wallet and XP events update overall totals. Named receipts update
   individual monster totals under the existing attribution rules.
4. `Addon.Refresh()` refreshes tracker rows. `Addon.DisplayData()` selects the
   preview or real dataset without redirecting real tracking into the preview.
5. Tracker row hover opens `Drops.lua`, which shows collected items only.

`RaynnaTrackerDB` is saved per character. Its existing keys include `mobs`, `money`,
`xp`, `scale`, `width`, `height`, `position`, `collapsed`, `hidden`, `demoPreview`
and `bestiary`. Monster records contain `name`, optional `npcID`, `count`, level
bounds, money/XP totals and item-keyed `drops`. Do not rename these keys without an
explicit migration. WoW writes saved variables on normal logout/UI reload.

## Bestiary data flow

Alt-hover selects an NPC or item. `LootSources.lua` supplies a reference result;
`Bestiary.lua` renders it in the same compact window. Item selections remain locked
for the current Alt press, allowing the pointer to cross other bag slots. Pinning
and hovering keep the panel open according to the existing lifetime rules.

Source entries can represent a monster drop, vendor or quest reward. Known
probabilities sort first. Conditional/quest-only flags, unknown probabilities and
provider labels must remain explicit. Reference results do not read personal kill
counts to estimate chances. Bundled metadata adds locations and extra source records. A newer enabled QuestieDB can supply metadata, with per-field bundled fallbacks.
The parchment material is generated by tools/build_parchment.py and bundled; it
has no atlas padding or transparent regions.

Portrait images are reusable GPU textures within the current UI session. A source
display ID and rendered texture are different things: the display map and recorded
monster IDs persist, while textures must be rebuilt after a UI reload. The loading
queue stops updating once every pending portrait is ready.

## Formatting and validation

Handwritten Lua uses four-space indentation, expanded control flow and descriptive
local names. Section comments divide state, rendering, construction and event
handling. `.stylua.toml` configures StyLua for Lua 5.1; `.styluaignore` excludes
generated tables and downloaded tools.

With `lupa` installed, run:

```powershell
python tests/test_addon.py
```

These mocked-runtime checks cover tracking, controls, sources, hover behavior,
portrait caching and saved-data serialization. They do not render WoW's UI.

For a presentation-only source refactor, save the original Lua files outside the
addon folder, then run:

```powershell
python tools/verify_refactor.py path/to/original-lua-files
```

This compares Lua 5.1 instructions, constants, function signatures and nested
functions while ignoring debug source lines and local-variable names. Generated
databases must match byte-for-byte. This is stronger than checking screenshots for
this kind of refactor: changed layout numbers, labels, events or callbacks would
change the executable comparison. It is deliberately too strict for new features.

The readability refactor was checked against
`tools/data-cache/refactor-before` (local, ignored by Git). No saved-variable or
game installation data belongs in that baseline.

## Rebuilding standalone metadata

`tools/build_metadata.py` exports the required fields from the installed QuestieDB
Forever metadata store at build time. It needs `cbor2` and `lupa`, records the source
TOC hash, and exports the relevant faction overlays. Static corrections are already
baked into the input TOC. The script also derives item-to-quest associations from
quest item objectives. Players do not need the exporter or its input addon.

The upstream licensing notice is retained in `LICENSE-QuestieDB.txt`; its historical
contributor caveat is not replaced by a claim of original authorship. The derived
snapshot is distributed on the GPLv3 terms described in that notice. Do not bundle
Questie's name/logo as branding or GearQuest's private texture assets.

Portrait preloading (1.14.1): login/reload queues saved real and demo monster
portraits, deduplicated by display ID, at two background requests per frame.
Visible hosts can claim pending textures and reuse completed ones immediately.
The three-second off-screen staging guard remains: no verified native readiness
signal is available in this implementation, so shortening it would risk the
previous black-square artifact. Preloading moves that wait ahead of scrolling;
it does not persist GPU textures or eliminate initial loading after a reload.


## Shared Raynna settings registry

Tracker/Bestiary and Talent Guide now bundle identical `SettingsRegistry.lua` bootstraps (version 1). `RaynnaModsSettingsRegistry` initializes one top-level category, registers independently owned pages by stable IDs (`foreverhunt`, `talentguide`), supports either package alone and late registration, and opens the actual registered category ID. Each addon builds its own controls and saves settings only in its declared saved variables.

Appearance synchronization uses registered getter/setter providers. An explicit appearance edit broadcasts to all registered packages, whose own setters persist it; packages do not read one another's private saved-variable tables. New Talent Guide appearance defaults may inherit a provider snapshot. Existing preferences are retained until changed.

Run `tests/test_settings_registry.py` for standalone and both-order tests, and `tests/test_talent_guide.py` for recommendations, adaptation, budget bounds, color ratings and animation controls. Bundle identical registry files in both releases.

Portrait preloading (1.14.2) also records up to 512 recently viewed NPC IDs in
`recentPortraitNPCs`, including Bestiary headers and item-source rows without
tracker kills. Login prewarms two textures per recent display so a tracker row
and a Bestiary header can use it simultaneously. The off-screen three-second
staging interval remains unchanged. Previously viewed Bestiary-only monsters
must be viewed once with this version to enter the new saved history. Background
preloading is paced; opening a panel immediately after login can still show a
placeholder until its texture completes staging.

`ForeverReference.lua` adds a partial, dated Forever NPC-drop fallback where
Classic creature records are absent. It also feeds reverse item lookups, retains
quest-only flags, and labels the NPC panel as a Forever reference. See packaged
REFERENCE-SOURCES.txt for URLs, coverage and update date. This is reference data,
not personal collected loot. No portrait mapping is inferred from similar NPCs.
